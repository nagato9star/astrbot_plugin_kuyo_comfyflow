# MOSS：提示词组装与工作流能力

## 按实际工作流选择能力

使用家族实际配置的模型、文本编码、尺寸和采样。

### 使用工具完成画图

自由生图使用 `comfyui_draw`，家族名从实时工具选择，画面内容写入 `prompt`。已有合适且实际可用的 MOSS 配方时，可以通过 `comfyui_lookup(type="recipe")` 了解用途，再用 `comfyui_recipe_draw`。编辑已有图片使用实际配置的编辑路由，不把生图工具当编辑接口。

普通请求不需要先展示一对 Positive / Negative 和采样说明。把内容交给工具，排队后按当前人格自然接话；后台交付结果后再结合原请求回应。用户明确索要提示词或参数时再展示相应内容。

### 按配置判断的能力

| 内容 | 当前怎么用 |
|---|---|
| 自然语言、已有 tag、主体动作和多人归属 | 可用于本次提示词，按家族 `prompt_style` 组织 |
| 原生图内文字、Layout 和多格构图 | 按用户需要尝试，效果以当前工作流输出为准 |
| 一般媒介、线条、笔触和配色描述 | 可按需求写 |
| 作者实验中的固定 16 步、0.6MP、50 步或 SLG 设置 | 保留为资料，不自动覆盖当前参数 |

媒介按用户需求选择。

原文第 15 章的一般媒介、技法和版式思路可作参考；第 14 章的原生 Layout 仍可按需求选读。

## 当前场景的画面描述

### 跟随用户选择媒介

写实、插画、漫画或混合媒介都按请求处理。用户没指定时，可结合当前聊天、已选工作流和参考图判断；只有选择会明显改变目标、而上下文又不足时才追问，不一律转成真人摄影。

写实时，摄影与光学词用于说明可见效果；插画时，用线条、色块、笔触、层次和配色说明风格。换媒介时一起整理与目标冲突的描述，不保留满篇摄影正文却只换开头一个画风词。

用户指定纯色背景、留白、cosplay、某个作品或特定人物时保留这些要求。角色名、作品名和画师名分别判断；不能因为原作者在自己的实验里删除过某类词，就把用户点名内容全部清掉。

需要画风时优先组织具体媒介和整体表现；已有当前模型可靠记录的名称可以按记录使用。

### 主提示词写完整

`prompt` 应包含本次画面的关键主体、动作、场所、构图、媒介及必要光色。MOSS 未确认独立风格或触发词槽位时，不把必要内容拆到可能不会被读取的字段里，也不假设插件会自动把这些字段补回主提示词。

已有 Danbooru tag 可结合目标保留或转写，不为了流程重新生成完全不同的角色、服装或场景。普通英文描述可与原语言文案并存；工具参数中的文本不需要把专名或图内文字强制全部转为小写。

多人时把每个人的位置、外观、衣服和动作放在自己的描述段里。先说清谁做什么，再补空间与光照，避免共享一长串发色和道具。普通场景可以是一段连贯短文；复杂层次再按人物或空间分组，源文的闭合标签方案可作为按需尝试的文案结构，不是必须执行的脚本协议。

### 参数与负向词保持独立

用户没有要求改变采样、尺寸或速度时沿用当前工作流。正文不塞“Steps=16”“CFG=3”或加载命令。

`negative` 只填写本次确需新增的排除项，是否追加或替换由实际槽位决定。原作者整套写实负向词不适合直接套进插画；已有配方也可能包含自己的负向约定。与模板固有排除项冲突时，追加相反词或传空不会自动撤销旧设置，应选择合适方案或调整工作流。

例：用户要雨后书店门口的水彩插画，就围绕人物动作、书店入口、湿地面、纸面笔触与配色写；无需附加摄影毛孔或作者固定的室内灯光模板。

## 文字、Layout 与实际参数

### 先决定是否需要 Layout

普通场景及少量文字通常可以用自然语言。需要精确文字位置、海报、明确物体关系或多格叙事时，再用原生 Layout。

可见文案保持原语言、标点、大小写和换行。人物描述和要印在图里的文字分开，别把工作流指令、编译说明或用户并不想画出的解释写进图面。

### 插件接收什么

普通描述直接作为 `prompt` 字符串。Layout 也作为 `prompt` 中的 JSON 字符串传入，使用模型输入的 `summary`、扁平 `items`、`abs_centralized` 和 `yxyx` 格式；不要套一个 `caption` 包装，再指望插件自动取出内容。

原作者或官方工具使用的编辑草稿、编译脚本不是本插件自动提供的能力。未转换的 `abs/xyxy` 草稿不能冒充最终模型输入。字段和中心原点的换算可按 [插件原有 Layout 说明](../../moss-image-prompting.md) 及资料第 14 章核对。

布局坐标必须与实际画布一致。需要精确像素时，通过 `comfyui_draw` 已公开且已映射的 `width` / `height` 指定；仅适用分辨率选择器的 `aspect_ratio` / `megapixels` 不能假定在所有模板里都可用。MOSS 宽高需要是 16 的正整数倍。

配方工具当前只提供方向和种子的临时覆盖；精确新画布等需求使用自由生图入口。缺少尺寸映射时处理真实报错，不把宽高偷偷写进正文或编造额外参数。

### 多格图

在整体描述中确定阅读顺序，再写每格的人物、动作、背景与文字。跨格保持角色外观，说明对白属于谁；原生 Layout 的元素仍使用全图坐标。

不把固定“2-panel”套用到用户要求的其他格数，也不擅自改文案去迁就模板。需要单页四格就明确四格；多格构图仍是一张输出图，不等于提交了四个任务。

Shift、SLG 层及其它未在工具中公开的控制项留给实际工作流。用户索要参数说明时，只说明已知的当前配置，不能把社区示例设置当作当前值。

### 结果怎么核对

发送状态以插件回包和完成事件为准。没有读取图片时，不声称文字已经正确或所有分格均符合要求；有图后再按本次目标看文字、角色与几何关系。修正针对具体问题，保留其余请求和当前工作流设置。
